១.២ យន្តការការពារដំណើរការស្ទួន (Single-Instance Lock Guard) ៖

១.៣ យន្តការ Smart DNS-over-HTTPS (DoH API Bypass) ៖


៧.២ ទីតាំង Log Files សម្រាប់ត្រួតពិនិត្យ ៖

• `crash_log.txt` ៖ Log កំហុសរត់ប្រព័ន្ធទូទៅ

៧.៣ ការដោះស្រាយបញ្ហាកំហុសដែលជួបប្រទះញឹកញាប់ (Common Errors & Fixes) ៖

១. កំហុស Telegram `409 Conflict: terminated by other getUpdates request` ៖
   • មូលហេតុ ៖ មាន Bot Instance ចាស់កំពុងរត់លើ VPS/Local ស្ទួនគ្នា។
   • ដំណោះស្រាយ ៖ លុប file `bot_instance.lock` រួចវាយបញ្ជា `taskkill /F /IM python.exe` (លើ Windows) ឬ `pkill -f python` (លើ Linux) រួចរັນ `python main.py --cli` ឡើងវិញ។

២. កំហុស Binance API `-2019 Margin is insufficient` ៖
   • មូលហេតុ ៖ ដើមទុន ក្នុង Futures Wallet មិនគ្រប់គ្រាន់សម្រាប់បើក Order ថ្មី។
   • ដំណោះស្រាយ ៖ បន្ថយទុនក្នុង ១ កាក់ (ឧទាហរណ៍ ៖ ពី $10.00 មក $5.00) ឬបន្ថយចំនួនកាក់អតិបរមា (ពី 10 កាក់ មក 5 កាក់) តាមរយៈ `/turbo_hedge TOP 5 5 AUTO 2.50 <PIN>`។

៣. កំហុស Binance API `-4164 Order amount minimum notional` ៖
   • មូលហេតុ ៖ ទំហំ Order សរុប (Amount * Leverage) ទាបជាង $5.00 - $10.00 USDT (កម្រិតកំណត់អប្បបរមារបស់ Binance)។
   • ដំណោះស្រាយ ៖ ប្រព័ន្ធបំពាក់ប្រព័ន្ធ precision formatting `get_futures_max_sellable_qty` លើ notional $6.50+ ដោយស្វ័យប្រវត្តិ។

៤. កំហុស Binance API `-1021 Timestamp for this request was 1000ms ahead of the server's time` ៖
   • មូលហេតុ ៖ ម៉ោងលើ VPS ដើរយឺត ឬលឿនជាង Binance Server Time។
   • ដំណោះស្រាយ ៖ ប្រព័ន្ធហៅ `sync_time()` អូតូ ឬ Admin អាច Sync Windows/Linux NTP Clock លើ VPS ដោយវាយបញ្ជា ៖ `w32tm /resync` (Windows) ឬ `sudo ntpdate pool.ntp.org` (Linux)។

៥. កំហុស `sqlite3.OperationalError: database is locked` ៖
   • មូលហេតុ ៖ Threads ច្រើនសរសេរចូល Database ក្នុងពេលតែមួយ។
   • ដំណោះស្រាយ ៖ `database.py` បំពាក់ WAL mode និង timeout 30,000ms អូតូ ប៉ុន្តែប្រសិនបើនៅតែកកស្ទះ Admin អាចរັນ `python fix_db.py` ដើម្បីដោះស្រាយ។

៦. យន្តការទប់ស្កាត់ Telegram Rate Limit (Leaky Bucket Limiter) ៖
